# Tool Resolver

`Resolve-CapabilityTool` consomme la Capability Matrix. Pour chaque technologie certaine, il retient uniquement les candidats dont la disponibilité est `available`, déduplique les commandes partagées et associe à chaque outil les capacités qu'il satisfait.

Le resultat par technologie contient `technology_status`, plateforme, `status`, `selected_tools`, `unresolved_capabilities`, `metrics` et `reasons`. Chaque entrée `selected_tools` expose aussi commande, capacités, source, version indexée, plateforme et `runtime_managed`. Les technologies ambigues ou absentes ne selectionnent aucun outil. Les resolutions peuvent etre `ready`, `partial`, `unavailable`, `ambiguous` ou `absent`.

La résolution est descriptive: elle ne lance pas les outils. L'orchestration Quick/Full/Ci/Fix demeure dans le Quality Gate et utilise encore ses chemins d'exécution propres. Les profils capacités/outils sont hardcodés dans `Get-CapabilityProfile`; aucun catalogue externe de profils n'est chargé.

La disponibilité est recherchée dans l'index Runtime, puis dans `.venv`, modules PowerShell, commandes visibles et binaires locaux historiques. Python n'est disponible depuis `.venv` que si le package sélectionné figure dans le snapshot indexé et si le hash du lock correspond; PSScriptAnalyzer exige la version indexée et les hashes manifest/arbre. Un outil issu du `PATH` ou d'un emplacement non indexé peut être utilisable mais n'est pas qualifié par plateforme dans l'index central.

La politique `all`, par defaut, retient les candidats complementaires disponibles et conserve les manques. La politique `alternative` retient uniquement le premier disponible dans l'ordre du profil; les alternatives indisponibles ne rendent pas cette capacite partielle. Les profils security Kubernetes/Helm la declarent pour Checkov/Trivy; cela ne prouve pas l'equivalence de tous leurs constats et ne modifie aucune sequence de controles. La deduplication par commande reste limitee a chaque technologie, sans budget ni graphe de dependances.

`metrics` expose `required_capabilities`, `candidate_occurrences`, `selected_commands`, `reused_assignments`, `unresolved_capabilities` et `duration_ms`. La duree couvre uniquement la selection apres construction de la matrice, pas le scan, le hash ni l'execution. Les reutilisations sont des correspondances supplementaires sur une commande deja retenue, pas une mesure de processus effectivement evites.

Une entree active non qualifiee provoque un refus immediat sans repli vers `.tools/bin`. Les chemins doivent rester relatifs et sous le runtime. Les SHA-256 des binaires, de l'arbre PSScriptAnalyzer et de la roue Python requise sont recalculés à la résolution; le lock Python est lui aussi comparé à son snapshot. L'absence ou l'altération donne un statut technique explicite. L'executeur protege aussi les copies historiques indexees avant demarrage. Les statuts ne constituent toujours pas une preuve de qualification native des contrôles. Voir [runtime.md](runtime.md).
